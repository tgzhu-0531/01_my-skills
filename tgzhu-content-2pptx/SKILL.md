# 内容 → PPTX 生成技能

将文章或资料转化为风格统一、版式严谨的 PowerPoint。全流程分步交互确认，未确认不写文件、不生成。

> 本文件只描述"**现行规则/约束是什么**"。变更历史（何时、为何演进）见 `CHANGELOG.md`。

## 1. 概述

- **输入**：IMA 知识库文章、公开链接（如 `mp.weixin.qq.com`）、粘贴文本、本机文件。
- **输出**：可编辑 `.pptx`（非图片）。
- **四风格**：企业风（深蓝渐变，克隆模板）/ 锋芒风（纯黑高对比）/ 文质风（奶油纸暖色）/ 商务风（McKinsey 咨询风，白底深字）。
- **目录约定**：技能包按职责分层——`engines/`（生成引擎）、`templates/`（模板）、`styles/`（设计稿）、`specs/`（规格 + `*-constraints.md` 排版约束清单）、`assets/`（二维码）。总览见 `README.md`。
- **核心工程原则**：模板克隆是唯一可靠的样式统一方案，代码绘制不可控。企业风克隆 `templates/enterprise.pptx`；商务风从空白画布代码绘制白底深字 McKinsey 版式（不依赖企业模板）；锋芒风/文质风从空白画布代码绘制（视觉 DNA 固化在 `engines/`）。

## 2. 执行约束（强制）

下列约束对所有生成任务生效，不可偏离：

1. **先读全文再执行**：加载技能后必须先读 SKILL.md 全文，严格按 Step 1~4 顺序与交互节点执行，不得跳过、合并、提前或自行发挥。
2. **严禁跳过交互节点**：弹窗/提问/等待确认任意一环未获用户明确回应，不得进入下一步。用户要求"跳过某步"时，须问"确认跳过？"后才可跳。
3. **无内容不生成**：用户未提供内容前，严禁直接生成大纲或 PPT。
4. **先确认后动手**：用户对某页提出修改时，先复述理解（指出具体页码与问题），达成一致后再修改；不猜测、不静默改动。修改文件或生成 PPT 前必须获用户确认。
5. **闭环交付**：生成完成后必须告知产物路径；本机无 LibreOffice 时无法自动渲染，提示用户在 PowerPoint 打开并按反馈迭代。
6. **文字零添加**：PPT 文字内容严格来自用户提供或抓取的材料，不创作、不引申、不补充事实或数据。版式与视觉可优化，但论点与数字须原文搬运。具体禁止项见 Step 4 红色规则 4。
7. **交互节点位置**：具体弹窗/确认形式与内容分别见 Step 1（弹窗 1/2）、Step 2（预览确认）、Step 3（弹窗 3）、Step 4（弹窗 4）。
8. **中文渲染**：所有文本须通过 `set_chinese_font()` 同时写入 `a:latin / a:ea / a:cs`，否则中文回退宋体（见 §4.4）。
9. **风格一致性**：同一份 PPT 只使用一种风格；四风格由 `engines/` 下对应引擎驱动，调用同一套版式原语（见 §4）。
10. **运行时依赖**：生成前探测 `python-pptx` / `lxml`，缺失时先提示用户是否安装，按用户确认执行（确认则装入隔离环境后重试，拒绝则停止并说明所需依赖）；不得静默跳过、不得直接抛错。

## 3. 工作流

### Step 1　内容来源与听众定义

**触发**：用户说"生成PPT""做个分享""做一份PPT"或加载技能时触发。

**弹窗 1：来源（单问题）**
加载后先输出启动提示，再弹问题："你打算如何提供材料？"

| 选项 | 说明 | 用户下一步 |
|:----|:----|:---------:|
| 1. **IMA 知识库**（推荐） | 从你的 IMA 个人知识库选择已有文章/文件 | 弹出知识库列表让选 |
| 2. **提供链接** | 提供 `mp.weixin.qq.com/s/...` 公开链接 | AI 文字回复"请把链接发给我" |
| 3. **粘贴内容** | 直接把文字粘贴到对话中 | AI 文字回复"请把内容粘贴过来" |
| 4. **本机文件地址** | 提供本地文件路径（多文件/大文件/PDF） | AI 文字回复"请提供文件路径" |

关键点：用户选完来源后，AI 用**普通文字**告知如何提供具体内容；用户用**直接打字**方式在聊天框输入链接/粘贴文字/路径（不再弹第二个冗余问题）。

**AI 获取内容（自动执行）**
收到具体内容后自动：用对应工具（WebFetch / Read / `mcp__ima-mcp__*`）获取完整内容 → 解析标题/作者/核心观点/关键段落 → 基于内容量评估页数 → 在脑中形成"这份内容大概能做几页"的判断。

**弹窗 2：听众 + 页数（带推荐）**
内容就绪后输出提示（"内容已获取（约 X 千字，N 个核心观点）。最后确认两个信息："），再一次性连续问两个问题：

- **问题 D1：听众是谁？** 选择决定大纲风格与内容侧重：

| 听众角色 | 大纲风格 | 内容侧重 |
|:--------|:--------|:--------|
| **研发团队** | 技术深度 | 架构、代码、数据流程、五层体系 |
| **产品/业务** | 应用价值 | 案例效果、能力边界、选型建议 |
| **管理层** | 结论先行 | 核心观点、ROI、建议方案 |
| **跨部门分享** | 通俗易懂 | 案例贯穿、类比说明、一句话结论 |

- **问题 D2：做多少页？** 选项数字≠页数。用户可接受推荐页数，也可在自定义框输入数字（"12页"或"8页以内"）。

> **⚠️ 页数歧义避让规则**：页数选项的 label 必须直接写页数（如"精简版（约 6 页）"），不能用数字编号（如"① 3页"）。因为用户可能在自定义框输入"1"意图是"1页"，会被误解为"选第 1 个选项"。用户直接输入数字 → 直接作为页数；用户点击选项 → 使用选项对应页数。

**内容丰富度要求（强制）**
每页内容必须有充足的原文干货支撑标题，不得只写骨架：

| 规则 | 不够（骨架） | 够（血肉） |
|:----|:-----------|:----------|
| **核心数据** | "8 个媒体槽" | 列出 8 个媒体槽具体内容：hero 图、2 支 mp4、截图、SVG…… |
| **表格** | 一句话总结 | **原文表格直接搬到 PPT 中** |
| **关键数字** | "3 轮封顶" | 写清楚：3 轮封顶 + 不收敛标 needs-human |
| **真实案例** | "有实际案例" | 展开讲：截图发现 9 页遮挡 → 自动修复 → 复检通过 |
| **对比逻辑** | "和模板库不同" | 列出 6 个对比维度：起点/密度/素材/渲染/质量/交付 |

**内容充实度检查清单**（提取每页时按序检查原文实际存在的论据）：
```
① 核心论点 —— 这页要讲什么（原文有）
② 数据支撑 —— 原文中涉及的数字/数量/版本
③ 案例支撑 —— 原文中展开的具体案例
④ 对比/表格 —— 原文中的对比/表格/结构
⑤ 金句结论 —— 原文中的总结性语句（→ 开头）
```
**核心原则：不延伸、不创作、只搬运原文。**
- 若某页原文支撑不足 3 条论据 → **不独立成页**，合并到相邻主题页。
- 宁可总页数少，也不要内容单薄的页面。
- 禁绝掺入原文没有的"创作性内容"。

**图片处理策略**
AI 工具无法从文章 Web 页面提取配图（只取文字）。策略：

| 场景 | 做法 |
|:----|:----|
| **原文配图** | 内容稿中标注 **`【图：原文配图位置说明】`** 占位 |
| **封面配图** | 可选：用 ImageGen 生成新图或留占位 |
| **复杂信息图** | 走 baoyu-infographic 生成或留占位 |

生成 PPTX 时，含占位的页面用文本框标记 `【图：XXX】`，用户打开 PPTX 后把图贴到对应位置。

**产出**：`outline.md`（大纲）+ `content.md`（详细内容稿），按听众角色与确认页数生成。

### Step 2　内容审查与确认（预览确认）

**核心规则：预览→发现问题→讨论修改。** 生成大纲和内容稿后，一次性交给用户预览，不用逐页确认。

- 一次性生成完整大纲 + 内容稿（`outline.md` + `content.md`），不用逐页生成。
- **内容稿交付方式（强制）**：
  - 必须使用 `present_files` 工具把 `outline.md` 和 `content.md` 作为**可点击卡片**输出，卡片中显示完整文件路径；用户点击后可在右侧预览完整内容稿。
  - 不得只在对话里贴文本摘要或段落；文本摘要只能作为补充，不能替代卡片交付。
- 用户指出问题：说"第 X 页要改……"或"整体调整……"，**口头讨论，只改确认要改的页**。
- 用户说"下一步""OK""确认"后，大纲和内容稿定稿，进入 Step 3。

### Step 3　风格选择与版式确定

**弹窗 3：风格（AskUserQuestion 单问题，四选一）**

内容确认后，向用户提问："内容已全部确认。请选择视觉风格："

**四风格选项**：

1. **💎 企业风**（深蓝渐变）— 默认，深蓝渐变底色 + 网格底纹 + 圆角卡片，匹配公司品牌
2. **🖤 锋芒风**（纯黑高对比）— 纯黑底 + 品牌青边框 + 巨号粗体，技术分享场景
3. **🤎 文质风**（奶油纸暖色）— 奶油纸底 + 衬线字体 + 柔和阴影，培训文档场景
4. **📊 商务风**（McKinsey 咨询风，白底深字）— 浅灰卡底 + 品牌青竖线 + 金高亮，商业汇报场景

**版式选择（实战验证）**：

| 用途 | Layout | 说明 |
|:----|:-----:|:----|
| **封面** | `Layout[0]` 标题幻灯片 | 企业风克隆模板自带 logo+标题线；锋芒/文质/商务风用空白页 `cover()` 绘制 |
| **内容页** | `Layout[6]` 4_标题幻灯片 | 自带 logo + 标题线 + 品牌组，**0 占位符**（无"单击此处"残留） |

> **版式原语的分类、调用约定与调用骨架代码见 §4.7（原语调用参考）。** Step 3 只负责与用户确认「风格 + 版式」；具体怎么把原语拼成 deck 属于生成实现，统一在第 4 章查阅。

各风格详细坐标、配色与视觉规则见 §5；原语调用参考见 §4.7。

### Step 4　生成确认与产物交付

所有配置就绪后，用 `AskUserQuestion` 弹出**弹窗 4（最终确认）**向用户汇总信息并请求确认（与弹窗 1/2/3 一致，**必须用弹窗而非纯文本**；**用户明确选「确认生成」之前，禁止执行任何生成操作**）：

```
准备生成 PPT，确认以下信息：
- 文件来源：{来源}
- 听众：{听众角色}
- 总页数：{确认页数} 页
- 风格：{企业风/锋芒风/文质风/商务风}
- 输出格式：.pptx
是否开始生成？（需要你的确认才会执行）
```

**红色规则 4：文字零添加（强制）**
PPT 页面上的文字必须严格等于用户提供的原文范围，不得自行补充。
- ❌ 不得在卡片/列表中添加原文没有的 bullet 条目
- ❌ 不得添加原文没有的收尾金句、总结句
- ❌ 不得对原文进行"展开解释"或"补充说明"
- ✅ 用户原文有多少字，PPT 就只展示多少字
- ✅ 表格/对比表等结构化内容按原文原样搬运

**违反案例（实战教训）**：用户提供三段式框架（理解/实操/驾驭各一行文字）→ AI 在卡片中自行添加"模型如何理解指令""什么场景擅长"等 bullet 条目 → 被用户指出"不要随意发挥"。

**生成后通知（必须输出）**：
```
✅ PPT 已生成
文件路径: {具体路径}/{文件名}.pptx
总页数: N 页

提示：文件在 PowerPoint 中可直接编辑文字。
如需美化排版，可在 PowerPoint 中进一步调整。
```

## 4. 跨风格通用层

下列规则对四风格统一约束，单一事实来源为 `engines/common.py` 与 `specs/*.md`。**通用层只放风格无关的规则与结构；四风格专属参数（色值/坐标/模板差异）见 §5。**

### 4.1 生成模型：一份 PPT = 首页 + 内容页 + 结束页

生成引擎按"页面类型"工作，而非按"规则主题"。一份 PPT 由三类页面顺序构成，每类由固定区块组成、受固定约束：

| 页面类型 | 构成区块 | 通用约束（详见） |
|:--------|:--------|:----------------|
| **首页（封面）** | 主标题 / 副标题 / 标签 / 二维码 | 必带二维码、刻意留白、不越界、不进右上 → §4.2.1 |
| **内容页** | 主标题区 `section_header` / 内容区 组件原语 / 金句区 `gold` | 三块通用约定 → §4.2.2；按场景选原语 → §4.3 |
| **结束页（结语 / hero）** | hero 问答 / 引文 / 二维码 | 结语收束、可带二维码 → §4.2.3 |

> 该脊是 §4 的组织顺序：§4.2 讲每类页面的区块与约束，§4.3 讲内容页的场景→原语→约定，§4.4 讲跨场景的通用原则。所有规则归属唯一、无交叉。

### 4.2 页面类型约束

#### 4.2.1 首页（封面）

- **构成**：主标题 + 副标题 + 标签（可选）+ 二维码（必带）。
- **主标题单行·字号智能算（强制）**：封面主标题**禁止换行**——用 `common.fit_cover_title(text, max_pt, min_pt)` 从风格上限字号向下反解「能单行容纳的最大字号」，`max_w = min(内容区宽, 页宽 × COVER_TITLE_MAX_W_RATIO=0.72)`，长标题自动缩小（如企业风 36→26pt、占屏 71.3%），**占屏宽 ≤ 整屏 72%，不得写死字号硬撑致换行/溢出**（裸 `fit_font_to_width(max_w=内容区宽)` 等于允许顶满，禁用）。对齐方向由风格 DNA 定（企业/文质/锋芒居中、商务居左，见 §5）。
- **封面文本「包住 + 上下居中」（强制·公共原语）**：封面主标题/副标题/标签一律用 `common.cover_line(slide, x, y, w, text, pt, color, bold, align, font=None, cy=None)`——内部统一「框高 = 实测字高 + 2×gap（上下等量呼吸）+ 强制 `vertical_anchor=MIDDLE`」，**禁止各引擎手写为 `tb_box` + TOP 锚点 + 写死 h**（否则锋芒/商务曾出现"框没包住、不居中"）。`cy` 给定时 y 视为文字垂直中心（保持既有视觉重心）；否则 y 为框顶，配合 `shape_bottom_in` 做 flow。`font` 可传衬线（文质 hero 宋体，不能强套雅黑）。
- **入口差异（风格专属，见 §5）**：企业风复用模板自带第 1 页，`first_slide()` 查找占位符文本框，`tf.clear()` 后 `p.add_run()` 填入新文字（**不清空整个 shape，不 XML 删除占位符**）；锋芒/文质/商务风用空白页 `first_slide()` + `cover()` 绘制。
- **二维码（必带）**：封面右下/底中放置 `assets/qrcode.jpg`，由 `cover()` 内部自动完成（企业风 `add_qr_enterprise`；锋芒/文质/商务 `cover_qr`，见 §5.0 坐标表）。调用方**不得在 `cover()` 之外再手动补一次**（否则封面画两遍）。`validate_deck(qr_on_cover=True)` 校验封面有图片。
- **留白与越界**：封面允许刻意留白营造呼吸感（§4.4 均衡要求不约束封面）；但形状仍不得超出页面（红线二，见 §4.4）。
- **金句**：封面通常不带底部金句；若需，走 `cover()` 内部逻辑，不另起 `bottom_gold`。
- **不进右上**：企业模板右上已有 Logo，二维码与标签避开右上。

#### 4.2.2 内容页

内容页由**三个固定区块**组成，跨风格一致：

1. **主标题区** — `section_header(s, h1, label, sub)`：
   - 永远**置顶左**（企业风品牌青置顶左、商务风 action title 置顶左；锋芒/文质同置顶左对齐）。
   - `label` 为**内容核心观点提炼**（如"巨头集体押注落地，三月投入超 75 亿美元"），**禁止「背景/价值」式分类词或「中文·English」双语类词**（validate_deck #8 会软告警）；`sub` 为副标题/说明，须为论点式陈述而非分类词。
   - **`sub` 渲染为标题下方单行副标题（label 青粗 + sub 灰，同一段落内联，不得拆两行、不得落页底）**：四风格一致——企业风原误把 `sub` 当页底金句渲染（压到金句线），锋芒风原把 label/sub 写进两个段落强拆两行，均已修正为单行；文质/商务本就单行。
   - 整页型原语（见 §4.7）内部已自带 `section_header`，**不得再调**；组件型原语（`timeline` / `two_column` / `card_grid`）**必须先 `section_header` 再调**，否则该页缺标题。
   - ⚠️ **`run_text` 追加 run 须 `first=True`**：`run_text(tf, text, ..., first=False)`（默认）会**新建一个空首段**再写，导致文本框首段留空行（MIDDLE 居中整体下移半行、或文本被推成多行）。须在首段续写第二个 run 时传 `first=True`，或手动 `p = tf.paragraphs[0]; p.add_run()`。
2. **内容区** — 组件型原语（或整页型原语的内容部分）：
   - 整体**垂直居中**于可用空间（`vcenter()`），内容不足一页时把正文块作整体上下左右居中，顶部锚点金句保持固定 y（见 §4.5）。
   - 按场景选原语 → 见 §4.3。
   - **正文关键词高亮（防平淡，强制）**：纯文字/时间轴等易空洞处，必须用核心词高亮制造视觉焦点——① 最多 **2 种高亮色**（青=主体·公司、金/琥珀=金额·投入，各风按 DNA 选色，见 §5）；② 只取主题最贴近的少数词，**量要克制，滥则乱**；③ 整页/整段同词**仅首次高亮**（去重，落实"整页一公司只强调一次"）；④ 统一由 `common.emph_runs`（公共骨架 `layout_timeline` 已接）或文质 `wenzhi._run_emph` 实现，生成侧在 `timeline` 条目传 `kw_teal`/`kw_amber` 字段（锋芒/商务/企业）或 `emphasis_teal`/`emphasis_amber` 列表（文质），**不得裸写纯文字**。
   - **金额即内容（不得遗漏）**：时间轴等条目可带 `amt` 字段（如 `"40亿$"`），公共骨架 `layout_timeline` 自动追加「 ｜ {amt}」并以**琥珀加粗**渲染（文质同逻辑；企业风走专属金额徽章）。金句若含关键数字（如"75 亿美元"）**不得截断省略**，并可经 `bottom_gold(..., kw_a=["75 亿美元"])` 高亮。
   - **`card_grid` 2×2 卡片网格红线（防压线/重叠，强制）**：
     - **序号 `tag` 与标题 `title` 同一行、MIDDLE 垂直居中**：tag 用 `concl_color` 强调色 **22pt 粗**（固定，不自适应、始终大于标题，原 28pt 自适应求解器已删）、title 用 `title_color` **14pt 粗**；数字占独立框（宽已收窄 NUM_W=0.52 避免推远标题）、标题紧随。不得上下错行（旧骨架写死 tag 在 `y+0.20`、title 在 `y+0.50` 两行，已改单行）。
     - **正文 bullet**：12pt 灰·左对齐·**"·" 前缀**·行距 1.3·段后 0.06″ 呼吸（旧版漏 "·" 前缀，已补）。
     - **结论 `hl` 居中 + 加粗 + 14pt 锁死**（禁 auto-fit 13：13/14 浮动本身是隐形不一致；受「金句禁换行」红线约束，文案须压到 1 行）：旧版曾 12pt·左对齐·不粗（已修为 14pt·CENTER·bold）。
     - **卡框高 = 内容自适应（紧抱内容）+ 整组垂直居中**：`ch = band_h(c) + 2*VPAD`（VPAD≈0.16 上下内边距，消死白），整组 2×N 在 `[y0,y_end]` **垂直居中**、框间距固定 0.32 与内部留白同频（视觉协调）；**不得写死 `ch=常数` 留大片死白**，也不得让卡内上下间距与框间距失调。
     - **金句分隔线/文字跟在正文之后**：分隔线 y = 正文末行底 + 安全间距（不写死到卡底），金句文字随之；**金句文字距卡底 ≥0.10″、正文不压分隔线、整组距金句线（GOLD_LINE_Y=6.50）≥0.10″**（旧骨架写死 `y+ch-0.36/0.30` 致金句距卡底仅 0.04″ 压线、正文重叠，已修）。
     - 调用方须先 `section_header` 再 `card_grid`、再单独 `bottom_gold`；商务风 `card_grid` 不自带背景，须先 `common.set_bg(WHITE)`。页眉须紧凑（副标题贴顶）以腾出卡片垂直预算。
3. **金句区** — `bottom_gold` 或原语 `gold=` 参数：
   - 永远**底中**（`PP_ALIGN.CENTER`），函数实现即为居中，调用方不得改左对齐。
   - **强制 `vertical_anchor=MIDDLE` + 默认 `bold=True`**（四风格统一加粗+居中，根治"框没包住文字/文字不上下居中/金句没加粗"）；由 `common.bottom_gold` 统一强制实现，各风格 `_gold` 调用不得改 anchor、不得传 `bold=False`。
   - **金句强制单行、禁止换行（硬红线，2026-08-01 新增）**：页底 `bottom_gold` 与卡内结论 `hl` 必须 1 行；字号固定（页底 16pt / 卡内 14pt），**靠精简文案到 1 行保证**，代码层 `common._guard_one_line()` 在生成期直接抛错（不靠压字号补救——压字号造成 13/14 等隐形不一致，正是用户反对的）。
   - **金句文字坐标统一为共享常量 `GOLD_TEXT_Y`（由页底反推，基准=企业风已验收的 text_y=6.65）**：四风格**一致**，杜绝此前散落硬编码（6.20/6.35/6.38/6.50 不一致、后三风偏高"离底太远"）；各风格 `_gold` 调用不得再写死 `line_y/text_y`（`GOLD_LINE_Y` 随"金句无分隔线"规则弃用）。
   - **四风格页底金句统一 16pt**（企业/文质 由 20/18 改 16，锋芒/商务本就 16），**只保留颜色 DNA 区分**（企业橙 `#F79646` / 文质暖金 `#C99322`（原赤陶橙 #D97757 已退役） / 锋芒青 `#00A7CB` / 商务金 `#C9A227`）；2pt 级字号差异读起来像 bug，故统一。
   - **金句上方无分隔线（通用规则，2026-08-01 新增，覆盖此前"分隔线退背景层"做法）**：页底 `bottom_gold` **不再绘制金句上方的分隔线**，四风格一致（含 P2 时间轴等所有走 `bottom_gold` 的金句）；`line_color` / `line_y` 参数已弃用（`common.bottom_gold` 已删画线逻辑，仅保留签名兼容调用方）。卡内结论上方的细分隔线 `card_divider` 不在此列，保留。
   - 金句是**原语契约**而非逐页手绘：`timeline / two_column / card_grid / summary / 各富原语` 统一接受 `gold=None`，传文本即自动渲染（含页码），不传则不画。仅在原语未走 `gold=` 时，才单独补 `bottom_gold(s, text)`。
   - 与二维码间距：底部金句与二维码必须保留 0.3″ 以上间隙（见 §5.0）。

#### 4.2.3 结束页（结语 / hero）

- **构成**：收束性内容（hero 问答 / 引文 / 大号三问）+ 二维码（可选）。
- **原语**：文质风 `hero_questions`（结语 hero 问答）；企业风 `transform_summary` / 各风格 `summary`（总结：大字居中 + 指标 + 引文）；`layout_hero_questions` / `layout_summary` 为对应骨架。
- **二维码**：结论页/末页的二维码由各富原语按需显式调用 `add_qr`（封面已内置，但末页可再加，见 §5.0）。只放封面 + 结论页，其他页面不加；右上禁放。
- **约束**：同内容页——形状不越界、金句/引文居中、与二维码留 0.3″ 间隙。

#### 4.3.1 垂直时间轴

- **原语**：`timeline`（锋芒/文质/商务基础原语）/ `layout_timeline`（骨架）/ 文质 `timeline_page`（整页富原语）。
- **结构**：左侧竖线（品牌青 `#00A7CB`）+ 圆点（品牌青实心）+ 日期（风格色右对齐）+ 事件描述（浅色）；关键数字可加圆角徽章。
- **布局**：基于事件数计算总高，整体垂直居中于内容区。
- **���头**：企业风竖线底部加 tailEnd triangle 箭头；其余风格按各自 DNA 决定是否加箭头（文质风仅在标签/金句处用暖金 `#C99322`，见 §5.3）。

#### 4.3.2 双栏

- **原语**：`two_column`（锋芒/文质/商务基础原语）/ `layout_two_column`（骨架）；文质 `definition_compare` 为整页级对比（见 §4.3.5）。
- **对等**：左右两栏标题必须**对等**——同字号（16pt Bold 风格色）、同 y 起始、均用 `run_text()` 首段写入（不得一栏 `run_text` 一栏追加，避免层级错位）。
- **分隔**：中间 gutter 可加极淡竖线（0.75pt）暗示独立区块，颜色随风格（见 §5.0 双栏分隔线色表）。
- **选型提醒**：一侧是人/角色罗列、另一侧是观点/告诫 → 企业风用 `profile_warning`（非对称深底双卡）；两侧等体裁等体量的简单并列才用 `two_column`（旧版原语未经 FDE 迭代，对照骨架核视觉语言）。

#### 4.3.3 多栏卡片网格

- **原语**：`card_grid`（锋芒/文质/商务基础原语）/ `layout_card_grid`（骨架）。
- **多值卡片**：内容 ≤ 4 项且需并列强调时用 2×2 网格；内容呈阶梯/序列关系时用阶梯式（左大右小）布局。
- **智能宽度**：2×2 卡片宽度按最长正文行字符数估算：`cw = max_chars * (14/72) / 2 + 0.39`，四舍五入至 0.5in，钳位 4.0–6.0in，整组居中（`x0 = (13.333 - cw*2 - 0.18) / 2`）。
- **卡片内部五区**（通用，所有卡片适用，对齐参考 ChatGPT 卡片视觉）：**① 数字**（固定 **22pt** 粗·强调色·左上独立框，作主标识；不自适应、始终大于标题且加粗——`layout_card_grid` 固定字号）｜**② 标题**（**14pt** 粗·标题色，与数字**同一行、MIDDLE 垂直居中**，数字占 **0.52″** 独立框（已收窄，避免推远标题）、标题紧随其后）｜**③ 内容**（12pt 灰·左对齐·**"·" 前缀 bullet**·行距 1.35 宽松·段后 0.10″ 呼吸；宽度由 `measure_text_width` 实算折行，不写死）｜**④ 分隔线**（内容↔结论间·隐约暗色退背景层·**跟在正文之后**不写死卡底）｜**⑤ 结论**（**14pt** 强调色·**居中·加粗**·分隔线下方，卡片内唯一高亮钩子；**锁死 14pt 禁 auto-fit 13、受「金句禁换行」红线约束须 1 行**，靠精简文案保证）。卡底透明 + 亮色细边框（轻、透气）。内部节奏：数字标题行 → 内容 → 分隔线 → 结论。
  - **卡框高 = 内容自适应（紧抱内容）+ 整组垂直居中（防压线/装不下，强制）**：`ch = band_h(c) + 2*VPAD`（VPAD≈0.16 上下内边距，消死白），整组 2×N 在 `[y0,y_end]` **垂直居中**、框间距固定 0.32 与内部留白同频；**不得写死 `ch=常数` 留大片死白**，也不得让卡内上下间距与框间距失调（视觉协调）。
  - **页眉须紧凑（关键前提）**：2×2 卡片需要 ~4.6″ 垂直预算（28pt 序号 + 2 行长正文 + 结论）。若 `section_header` 的副标题位置偏低（如锋芒/文质原副标底部 ~1.85″），可用高度仅 ~4.5″，28pt 装不下 → **副标题必须贴顶紧凑**（锋芒标题 26pt+副标紧随、文质青线作标题下划线 y=1.02″/副标 1.24″），为卡片腾出预算；否则自适应引擎只能下探到 22–24pt。
  - **⚠️ 旧版三 bug（已修，不得回退）**：① 序号曾用 body_size(12pt) 而非 **22pt**；② 结论曾用 12pt + 左对齐 + 不粗（应为 **14pt** 居中加粗）；③ 正文曾无 "·" 前缀（应为 bullet）。三者均因实现未对齐本五区约定所致。

#### 4.3.4 2×2 闭环（四象限）

- **原语**：`value_grid`（文质）/ `value_loop`（企业）/ `layout_value_grid`（骨架，`loop=True` 等长循环箭头 + 四卡等距 0.7，`loop=False` 纯并列 + `solve` 切求解器与固定节奏）。
- **先判关系**：有因果/时序（如 发现→转化→负责→沉淀）→ 用箭头连接；纯并列四值 → 去掉箭头，纯对称网格。
- **用箭头时**：上下左右四箭头**等长** → 四卡上下左右间距全等（最干净对称）。
- **不用箭头时**：四卡间距**大气**（不紧凑不松散），四向一致。
- **四卡等宽等高**；并列卡整组同号（以最密卡为约束）。

#### 4.3.5 定义对比

- **原语**：`definition_compare`（企业风富原语 + 文质风整页富原语）/ `layout_compare`（骨架：`compare.right_card` 切裸区 + 竖线 + 圆底× / 透明青边卡 + 文本✕；bullets 支持 `(text, kw)` 高亮）。
- **语义**：左栏 = 定义/是什么，右栏 = 不是什么（如 FDE ≠ 售前/实施/驻场外包）。
- **正解描述框**：按内容行数自适应高度 + `word_wrap`，禁写死单行高（避免折行溢出，validate 第 5 项抓出）。

#### 4.3.6 表格

- **铁律**：垂直居中（所有 cell `vertical_anchor = MSO_ANCHOR.MIDDLE`，不得 top 对齐）；智能列宽（禁止等分，按内容性质指定 `col_widths`，短列窄长列宽）；深底配色（表头与数据行同底色，仅以文字颜色 + 加粗区分层级，禁 PowerPoint 默认白/灰交替，禁表头用高亮品牌色导致与暗底不协调）。
- **字号与行高**：表头 12pt Bold，数据行 11pt，行高 0.42in（按行数动态计算）。

### 4.4 跨风格通用原则

以下规则对所有场景、所有风格生效，单一事实源 `common.py` / `specs/*.md`。

- **中文渲染**：所有文本必须通过 `set_chinese_font(run)` 同时写 `a:latin / a:ea / a:cs` 三个元素，字体统一 `微软雅黑`；仅设 `run.font.name`（latin）会导致中文回退宋体。由 `common.run_text()` 封装，引擎内一律经此函数写文本，不得 `p.text = ...` 后不设东亚字体。**Bold 设置**：建议 paragraph 级 + run 级双重设置，确保 PowerPoint 各版本均渲染生效。
- **间距体系**：单位内（同主题连续条目）`space_after = 4pt`；单位间（不同主题/模块）`space_after = 24pt`；卡片标题 → 卡片内容 `space_after = 14pt`；双栏区域标题 → 首个子项标题同 14pt（子项内部标题→正文保持 4–6pt）。`run_text()` 默认段后距 4pt，覆写后用于卡片内部 14pt。**页面级布局（强制）**：四风格所有整页版式须引用 `common.CANVAS_*`（X0=0.80 / TOP=1.88 / BOT=6.20）统一边距，禁止引擎写死 `0.46`/`0.60` 等漂移值；内容块须 `vcenter()` 垂直居中（正文居页中、消去底部大白），块/段间距用 `auto_gap()` 按内容量自动推算（不空不挤），复合页/多块结构（如 `layout_loop_page`）的余量须自动均摊到块间间隙（stretch），顶/底留白收敛，不内紧外松；段内行距统一 `SP_LINE=1.22`（用 `set_leading` / `run_text` 默认，禁止引擎写死行距倍数）。
- **文本框与框高紧贴**：所有文字框 `margin_top/bottom/left/right = 0`，`auto_size = NONE`，`vertical_anchor` 按需求设 TOP / MIDDLE。段落行距统一 `common.SP_LINE = 1.22`（约 22% 额外行距，单一事实源）。边界约束：页面 16:9 = 13.333 × 7.5in，所有 `tb(x, y, w, h)` 须满足 `x + w ≤ 13.333` 且 `y + h ≤ 7.5`。**框高紧贴文字**：单行角色文本（主标题/副标题/标签/金句/章节标题等）一律用 `common.tb_box_hug(slide, x, y, w, text, pt, color, bold, align, gap=0.06~0.10)`——框高 = `measure_text_height(text, pt, w) + gap`，**绝不写死偏大的固定 h**。多段落或需精确控制的再用 `tb_box`。`validate_deck` 第 5 项会扫描"高≤0.6 的文本框，文本实测宽>框宽即判换行"，反向逼出框高/框宽都按内容实测。**自然行高地板**：`measure_text_height` 每行高取 `max(SP_LINE, NATURAL_LH=1.35)`——PowerPoint 不会把行渲染得比字形自然高更窄，行距倍数偏小（1.22<1.35）会被字形顶起，大字（如 54pt）若不用地板，框会比真实渲染矮 ~0.11″，底部笔画被压（"框没包住文字"）。**flow 布局**：装饰线/下一元素的 y 用 `common.shape_bottom_in(tf)` 从前一元素**实际框底**推导，禁止硬编码 y（否则大字变高时压中文字/线，如锋芒封面下划线曾嵌入标题底 0.1″）。
- **字号下限与自适应**：正文/正文类最小 **12pt**（`common.py::TYPOGRAPHY` 的 `body_small` / `badge` 已锁 12pt），更小不可读；宽松区用 14pt（`body`）。主标题/副标题/金句字号固定；其余内容区文本**正文 ≥12pt 底线**，用 `common.solve_card_fonts()` 按容器高智能求解（间距同步区间弹性），禁止手工指定固定字号；并列卡整组同号（以最密卡为约束）。
- **居中对称 / 内容饱满**：内容簇在页面内**水平居中**，左右页边距**对等**（|差|<0.05in）；不是"贴左缘对齐其他页"，除非该左缘本身就是居中结果。内容区整体**垂直居中**于可用空间（如企业风 1.85→6.30）。禁止一侧文案挤作一团、对侧大片空白。每页正文块须填满可用区，不得"上紧下空"或"左紧右空"。
- **红线与布局规则（强制）**：红线一——每行文字距任何线 ≥ 0.10″，内容不允许贴线；红线二——卡片/形状不允许超出页面（≤13.333 × 7.502），生成后必跑 `validate_deck`。上下间距按内容量智能算：内容少→放大，内容多→收紧，区间 0.10~0.16″。间距层级：标题↔正文 > 段落↔段落 > 段内行距（下限逐级递减）。行带高取行内最大字号。段间线：内容多→不画（几何符号分段），内容松散→风格自由决定。箭头粗细随底色：**深底 2pt**（企业/锋芒）、**浅底可 1.5pt**（文质/商务，validate_deck 范围 1.5~2.5 内）；U 型闭环回流统一走 `common.loop_return_u(centers, node_bot, u_bot, color, w)`（起终点均节点底中、左右对称）。机制：`common.solve_card_fonts(points_list, body_w, container_h, spacing_range, domains)` + `common.fit_gaps()`；各风格传自己的间距区间/字号域。
- **尺寸由内容实测、取中间值**：文本框**宽**用 `common.measure_text_width` 算最长行宽（不凭感觉、不撑满）；文本框**高**用 `common.measure_text_height(text, pt, w) + gap` 经 `tb_box_hug` 紧贴文字。两函数跨 OS 探 CJK 字体（Win 微软雅黑 / Mac PingFang / Linux Noto），无字体无 PIL 时按字符估算兜底。卡宽/留白用 `measure_text_width` 实算后取"刚好容纳内容"的对等值（卡宽=最长行+内边距+缓冲）；**禁止在两极端间横跳**——太窄↔为"安全"撑满内容区；边距太大↔压到 0 边距。每次迭代都从测算值出发微调，不凭"上一版太宽就反向压窄"拍脑袋。
- **视觉层级 / 装饰退内容进 / 颜色常量化 / 对称**：每区一个高亮，卡片内高亮只给"数字+结论"，内容保持安静灰。箭头用"颜色退、线宽进"（同族低明度 + 加粗），不与高亮撞同色。全部角色命名常量（见各引擎 PALETTE），不写魔法值；箭头色须与高亮色区分。中心圆是沉重锚点且易出兼容问题，对称簇 + 可选等边箭头更稳更干净。**分隔线 / 卡片边框一律极淡贴背景，退到背景层不抢戏；浅底内容卡叠柔和投影 `outerShdw`（common.add_soft_shadow）抬升，近黑底（锋芒）靠卡底填充差（`#111` vs `#0A0A0A`）抬升、不加阴影**（2026-08-01 收尾）。**
- **流程纪律**：视觉迭代先复述理解 → 确认 → 再实现，不"先改一版给你看"（见 §2 第 4 条）。
- **视觉设计铁律与色彩 DNA（四风格通用）**：单强调色收敛、层级靠颜色拉不靠字号、阴影克制（≤8%）、页眉节奏、底部结论（否决独立结论带）、字体分工（宋体标题/黑体信息）、反模式清单与验证闭环（含 `p:sp` 命名空间坑 + 文件锁坑），已分层沉淀于 `references/design-principles.md` **§9–§13**。新增风格/原语须先读、不得违反；其中"卡片标题不加大""金只点编号与页底结论"为用户红线。

### 4.5 视觉增强原则（huashu 哲学）

借鉴"反 slop"原则：**少框、分层、有视觉锚点**。
- **去框化**：一个页面出现 4+ 个矩形框会显平淡、像清单 → 改为纯排印分层。字号层级差 > 2 阶：hero 大字（36pt）→ 标题（18–22pt）→ 主文（13pt）→ 副文（10pt）。
- **关键术语/数字**：用放大 + 品牌色单独成视觉焦点。
- **暗底文字对比（强制）**：纯黑/深底上的文字须保证可读——正文/副标题 ≥ 4.5:1、辅助/标签 ≥ 3:1（WCAG）。锋芒风灰阶地板：封面副标题 ≥ `#CCC`(≈12:1)、标签/辅助 ≥ `#B3B3B3`(≈9:1)；**禁用 `#666`(仅 3.4:1) 级灰做正文/标签**，投屏几乎不可见。
- **正文区居中**：内容不足一页时，把正文块作为整体在剩余空间里上下左右居中，顶部锚点金句保持固定 y 不移动。
- 该原则在企业风为强制（见 §5.1）；锋芒/文质/商务风可酌情采用。

### 4.6 布局骨架 × 皮肤（架构）

- 布局几何只写一份在 `common.layout_*`（骨架）；四风格只提供皮肤（`SKIN_*` dict：配色/字体/字号/箭头/卡样式），**骨架不引用任何具体色值/字体，皮肤不写布局坐标**。
- **企业风是布局样板**：新场景先在企业风调通布局 → 公共骨架定稿 → 文质/锋芒/商务用各自皮肤自动生效（生成时换 skin 重跑即可，杜绝"企业风迭代了、其它风格还是旧的"）。
- 皮肤契约字段：`bg / fonts{head,body,mute} / cap{size,bold,color} / node{size,bold,color,sub_size,sub_color} / card{title_size,title_color,sub_size,sub_color,body_size,body_color,concl_color,line,line_w} / arrow{color,w} / tail_bar / line_spacing / timeline / compare / value_grid / profile / transition / hero`（各原语专属字段见骨架 docstring）。
- 已骨架化（12 个）：`layout_loop_page` / `layout_timeline` / `layout_card_grid` / `layout_compare` / `layout_value_grid` / `layout_profile_warning` / `layout_six_step` / `layout_talent_strip` / `layout_transition_rows` / `layout_hero_questions` / `layout_two_column` / `layout_summary`。
- **引擎层已全部改调骨架**：文质风 12 个原语、企业风 6 个富原语、锋芒/商务基础原语——原函数签名全部保留，业务脚本零改动；`enterprise.timeline` 卡片式（homePlate+徽章+虚线）为定稿特色保留在引擎层。新增场景一律走"企业风调通 → 骨架定稿 → 三风格换皮肤生效"。验证：`四风格骨架试点v4.pptx`（12 骨架 × 4 皮肤 = 48 页）validate PASS + 文质业务回归 PASS。

> 实战锚点：企业风 `value_loop`（2×2 闭环页，见 `specs/enterprise-constraints.md`）即 §4.3.4 / §4.4 的落地样板——等边箭头、卡宽内容实测、框内五区规则齐备。封面允许刻意留白营造呼吸感，本节约衡要求不约束封面。

### 4.7 原语调用参考（分类 + 调用骨架）

> **⚠️ 调用约定铁律（实战踩坑）**：版式原语分两类——
> - **整页型**（内部已自带 `section_header` + 底部金句 + 封面二维码）：`cover`，以及企业风专属富版式 `definition_compare`、`value_loop`、`work_people`、`transform_summary`、`profile_warning`（**这 5 个富版式均为企业风专属，锋芒/文质/商务均不存在**）。直接调即可，无需再调 section_header。锋芒/文质/商务的整页封面用 `cover`，其余页用 `section_header` + 组件型原语组合。
> - **组件型**（纯版面、**不自带标题/副标题/金句**）：`timeline`、`two_column`、`card_grid`。
>   调用方必须**先 `section_header(s, h1, label, sub)` 再调组件型原语**，否则该页会缺标题/副标题；金句通过 `gold=` 参数由原语内部渲染（见 §4.2.2），不传则不画。

> **封面二维码已内置**：四风格 `cover()` 内部已画封面二维码（企业风 `add_qr_enterprise`；锋芒/文质/商务 `cover_qr`，见 §4.2.1 / §5.0）——**调用方不得在 `cover()` 之外再手动 `add_qr`，否则封面画两遍**。
