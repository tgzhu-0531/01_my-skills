# 设计准则（跨风格通用，skill 级）

> 适用：四风格引擎（enterprise / fengmang / wenzhi / business）。
> 定位：**只沉淀机制与原则，不约束各风格的视觉个性**。各风格配色、字体、卡片样式仍由各引擎专属实现。

---

## 1. 总则

### 1.1 共享机制，不共享审美
- 公共层 `engines/common.py` 只放**几何/工具/常量**（线宽、间距、箭头绘制、二维码、校验、内容卡通用机制 `content_card` / `card_divider`）。
- 各引擎 `enterprise.py` 等只放**本风格的配色与版式**（颜色、卡片样式、特定原语渲染）。
- 任何"长什么样"的东西不要提到公共层；只提"怎么画""怎么量""怎么验"。

### 1.2 内容为主，装饰退后
- 内容是主角，装饰（箭头、连线、分隔线）退到背景层：颜色退、线宽进（沉稳色 + 适度加粗）既可见又不抢戏。
- 高亮名额留给重点元素（结论/金句），不撒胡椒面。

### 1.3 尺寸实测算
- 卡片/文本框宽度用真实字体度量（PIL 量最长行），加内边距定宽。
- 禁止"设个值说够用"或"为安全直接撑满"。

## 2. 四风格概览

| 风格 | 底色 | 字色 | 箭头色 | 模板来源 | 适用场景 |
|------|------|------|--------|---------|---------|
| **企业风** (enterprise) | 深蓝渐变 | 白 | 白 | 克隆 `templates/enterprise.pptx` | 公司正式汇报 |

## 3. 公共布局规则（四风格强制）

> 所有机制在 `common.py`（几何层，不绑配色/字体）。四风格一律引用，禁止引擎写死字面量。

### 3.1 画布与安全边距
- `CANVAS_X0 = 0.80`、`CANVAS_X1 = 12.53`、`CANVAS_CW = 11.73`（左缘 0.80 → 右缘 12.53）。
- `CANVAS_TOP = 1.88`（标题/副标之下）、`CANVAS_BOT = 6.20`（页码之上）、`CANVAS_CH = 4.32`。
- 禁止在引擎里写死 `0.46` / `0.60` / `0.80` 等边距字面量。

### 3.2 垂直居中（杜绝底部大白）
- 任意内容块在 `[CANVAS_TOP, CANVAS_BOT]` 内**垂直居中**：`y = vcenter(block_h)`。
- 内容超出可用区时回退顶对齐，不鬼畜居中。
- 上下留白均衡，消除"顶部塞满、底部空一大块"的空感。

### 3.3 间距按内容自动计算
- 块/段间距由可用空间与内容量推导：`gap = auto_gap(total_h, n)`。
- 内容少→间距放大填满页面（不留大白）；内容多→间距收紧（不拥挤）。
- 间距夹在 `[SP_GAP_MIN=10pt, SP_GAP_MAX=40pt]` 内防极端。
- 顶部对齐 + 固定步进（如 `y + 0.82 + j*0.32`）视为**违规**，改用 `vstack` / `vcenter` + `auto_gap`。

### 3.4 间距节奏常量
- **段内行距**：`SP_LINE = 1.22`（禁止引擎写死 `line_spacing` 倍数）。
- **段间**：`SP_PARA_INTER = 24pt`（可被 `auto_gap` 覆盖）。
- **段内多行额外留白**：`SP_PARA_INTRA = 4pt`。
- **单位内连续条目** `SP_UNIT=4pt`、**单位间** `SP_GROUP=24pt`、**卡片标题→内容** `SP_CARD_BODY=14pt`。
- 同页多块间距取统一中间值（如企业风 `0.22″`），不要一段 0.04″ 一段 0.7″。

### 3.5 密度原则
- **饱满但不拥挤，不留大白**：内容应铺满内容区、上下留白均衡。
- 既不允许底部大片空白，也不允许元素贴边互压。
- 实现靠 3.2（居中）+ 3.3（自动间距）共同保证，不靠手工调固定 y。

### 3.6 字号自适应
- **固定字号（仅三者）**：主标题（H1）、副标题（label/sub）、底部金句（gold）——字号由各风格角色表钉死，不得因内容量调整。
- **内容区字号可自适配**：正文 / 卡片标题 / 要点 / 标签等，允许按版面自动计算合适字号，**下限 12pt**。
- 机制：`fit_content_font(texts, box_w, box_h, font_name, min_size=12, max_size=…)`——按实测字宽折行，取能放下的最大整数 pt。
- 内容稀疏→放大更大气；内容密集→收紧但不低于 12。
- 并列卡一致性：同一网格内同级文本取**整组最小适配值**统一应用。

## 4. 公共机制（common.py 实现）

### 4.1 箭头 / 闭环
- **线宽**：`LOOP_ARROW_W = Pt(2)`，跨风格通用。
- **颜色**：由引擎传入，`common.loop_arrow(slide, x1,y1,x2,y2, color=本风格色)`。
- **闭环回流箭头**：起点与终点必须都落在节点的底中，左右对称，形成可读闭环。

### 4.2 带框内容卡
> 适用：四风格所有带框内容卡（如四宫格价值卡、对比卡等）。
> 不适用：实心密集容器卡（如画像/告诫卡 `profile_warning`）——按 §4.3 实心容器卡处理。

**框体规则：**
- 一律：透明底 `fill.background()` + 风格强调色亮边框。
- 线宽 1.25pt、小圆角 `adj=0.04`。
- **无浅底例外、无实心底例外**。
- 调用：`content_card(slide, x, y, w, h, accent, line_w=1.25, adj=0.04)`。

**框内四段式 + 分隔线耦合：**
- 线性顺序固定：**标题 → D1 → 正文 → D2 → 结论**（正文恒为必有核心段）。
- **D1（标题↔正文）**：仅当有标题时可存在，不强制。强调色细线、宽 = 标题实测宽 + 缓冲（不通栏）。
- **D2（正文↔结论）**：仅当有结论时存在。风格主分隔线色、通栏。
- **耦合**：缺标题 ⇒ 无 D1；缺结论 ⇒ 无 D2。
- **松散正文**：子项间可加极浅近底色子分隔线，仅做底线不抢戏。

**标题段三种呈现（任选其一）：**
1. 带数字·数字加重：序号大字号 + 强调色 + 粗，与标题同行。
2. 不带数字：仅标题，无序号。
3. 带数字·数字作普通文本：序号当普通文字，同标题字号不加重。

### 4.3 实心容器卡
> 适用：内容量少的页面需要容器补重时（如画像/告诫卡）。

- 用实心容器提供视觉重量，不靠填字凑饱满。
- **禁止为填空而扩写文案**（违反"文字搬运原文、零添加"）。
- 深底风格用深色实心卡；浅底风格用浅灰卡 + 深字。
- 小圆角 `common.rounded_card(adj=0.04)`；默认 0.16667 太软像移动端 UI。

### 4.4 分隔线体系
- **两级制**：行间用"极浅近底色"线只做底线（几乎融入背景）；结论行上方用"略亮"线提示升华。不是所有线一个色。
- **头身分界线**：卡内标题下加细强调线，宽 = 标题实测宽 + 0.3″（不通栏），是最低成本的卡内层级手段。

### 4.5 单行防换行
- 副标题 / 金句文本框宽度被写死偏窄时，长文本会在框内折行（页面整体还有余量）。
- 一律用 `fit_single_line()` 按实测文本宽设框宽，杜绝假换行。

### 4.6 生成后校验
- 每次生成后调用 `common.validate_deck(path)`，检查：
  1. 无形状越界（≤ 13.333 × 7.502）；
  2. 封面有二维码图片（如该风格需要）；
  3. 所有箭头线宽 ≈ 2pt；
  4. 箭头色 ≠ 底色（防浅底误用白）；
  5. 单行文本框不换行（扫描高度 ≤ 0.6 的文本框，实测宽 > 框宽即报）。
- 不能只信"跑通没报错"——要反向读 XML 验证关键参数。

## 5. 内容组织原则

### 5.1 内容建模（对照页拆字段）
- 对照内容（如「三个转变」「定义对比」）把长句拆成结构化字段（如 `from / to_title / to_desc` 或 `negatives / positive`）。
- 扫描性 > 堆字；渲染时旧态/新态分栏，读者一眼读懂方向。

### 5.2 非对称卡宽
- 等宽只配等量内容；两侧内容体量不对等时用宽度匹配体量（如左 4.90″ / 右 6.83″）。

### 5.3 短词两列排布
- ≤ 8 字的短词条 4 条以上时两列排、超长条独占行——"N 行稀疏变 N/2 行密实"，零添加文字解决留白。

### 5.4 参考物工作法
- 外部原型（GPT 等）只做参照物——吸收其对的，用已验证手法超越其不足；不当标准答案照抄。
- 看图注意极浅元素易漏（浅分隔线等）。

## 6. 各风格专属规则

### 6.2 锋芒风 (fengmang)

- **箭头色**：白色。

### 6.3 文质风 (wenzhi)

### 6.4 商务风 (business)

- **基础原语**：`cover` / `section_header` / `timeline` / `two_column` / `card_grid` / `summary` / `bottom_gold`。

## 7. 协作纪律

- 任何视觉/版式修改：**先反馈理解、与用户达成一致再动手**，不直接改了交付。
- 不在"太窄↔撑满""边距太大↔太小"两个极端间横跳；要测算出的中间值。
- 新风格/新原语先各自生成验证效果，再决定哪些机制值得下沉公共层。

---

## 8. 沉淀原则

- 当前 `work_people` / `value_loop` / `definition_compare` 等富原语仅企业风实现；其它三风格只有 7 个基础原语。
- 不要急于把企业风版式外推；先分别生成各风格 deck，看各自效果，再回头决定共享哪些机制。
- 其它三风格封面是否带二维码，同样先验证再定（勿盲目照搬）。

## 9. 视觉铁律（跨风格，不可违反）

> 来源：2026-08-01 商务风/文质风 P3 经 ChatGPT 评审 + 专家取舍后收敛的通用原则。四风格一律适用，新增风格不得违反。
> 定位：**只沉淀"怎么才算好看/克制"的通用纪律，不约束各风格视觉个性。**

### 9.1 单强调色原则（金色收敛）
- 每页**至多一种强调色**（金/暖金/或暗风的青，按风格 DNA 定）。
- 强调色**只用于两处**：① 卡片编号 ② 页底最终结论。其余一律用主色/辅助色。
- 卡片内部结论**用主色深蓝灰**，不用强调色，避免与编号/页底抢戏。
- **反模式**：编号(金)+卡片结论(金)+页底(金) 三处同色 = 9 个"最高优先级"焦点，读者不知先看哪（ChatGPT 评审核心问题①）。

### 9.2 层级靠颜色拉，不靠字号
- 卡片标题字号守四风格统一锁值（14pt），**不加大**（用户红线）。
- 卡内"编号/标题/正文/结论"四级靠颜色分工消解竞争焦点，不靠放大某一级。
- 字号只在 H1/副标/金句固定 + 内容区自适应（≥12pt），见 §3.6。

### 9.3 阴影克制（去 UI 感）
- 浅底卡片阴影透明度 **≤ 8%**（alpha ≤ 8000）；文质可更轻 6%（6000）。
- 边框 0.75–1.0pt 极淡（贴背景）；圆角 6–10px（adj 0.03–0.04）。
- 暗底风格（锋芒/企业深蓝）**不叠阴影**，靠填充差抬升。
- 公共层 `content_card` / `rounded_card` / `add_soft_shadow` 阴影默认已改 8%（旧默认 35% 偏重已弃用），个别风格可再调淡（如文质 6000）。`validate_deck` #6 对 >12% 报 WARN。

### 9.4 留白与节奏
- 页眉/页脚/卡片间距走自动测算（§3.3），不在两个极端横跳（太窄↔撑满、边距太大↔太小）。

## 10. 色彩 DNA 规范（三级体系 + 四风格对照）

### 10.1 三级色彩体系（每风格必定义）
| 角色 | 含义 | 占比建议 |
|------|------|---------|
| 主色 primary | 主标题 / 卡片标题 / 卡片结论 | ~70% |
| 辅助色 auxiliary | 结构 / 编号 / 章节标签 / 关键词（青） | ~20% |
| 强调色 accent | 仅编号 + 页底最终结论（金/暖金；暗风用青代） | ~10% |
| 正文 body | 正文说明 | — |
| 辅助文字 mute | 页码 / 署名 / 次要 | — |
| 背景 bg | 页面底色 | — |

- 强调色占比 ≤10%，**不大面积出现**。

### 10.2 四风格色彩 DNA 对照表
| 风格 | 背景 | 主色(标题/结论) | 辅助色(结构/编号) | 强调色(编号+页底) | 正文 | 卡边框 |
|------|------|---------------|------------------|------------------|------|--------|
| **企业** enterprise | 深蓝渐变 | 白 `#FFFFFF` | 品牌青 `#00A7CB` | 青（单色体系，编号+结论同青） | 浅灰 `#CCCCCC` | 极淡 `#D2D8DC` |
| **锋芒** fengmang | 纯黑 `#0A0A0A` | 白 `#FFFFFF` | 青 `#00A7CB` | 青（同暗风，金句=青） | 浅灰 `#999999` | 近黑 `#444444`（三阶调亮定稿，黑底上可见不抢戏） |
| **文质** wenzhi | 米白 `#F7F4EE` | 深蓝灰 `#30485B` | 青 `#00A5C8` | 暖金 `#C99322`（仅页底结论） | 灰 `#4D5054` | 暖灰 `#DDD8CE` 0.75pt+6%影 |
| **商务** business | 白 `#FFFFFF` | 深蓝灰 `#334B5E` | 青 `#00A6C8` | 金 `#C99A1A`（编号+页底） | 深灰 `#3F454B` | 浅灰 `#E5E9ED` 1.0pt+8%影 |

> **暗风 vs 浅风**：企业/锋芒为暗底**单色强调**（青），编号+结论+金句全青，天然干净，无需"金收敛"；文质/商务为浅底**双色**（青管结构 + 金/暖金点结论），须严守"金只点编号与页底结论"。两套逻辑都落在一个 DNA 表内。

## 11. 组件级克制规范

### 11.1 卡片（content_card / rounded_card）
- 透明底 + 极淡边框 + ≤8% 轻影（见 §9.3）。
- 卡内四级：**编号**(辅助色,轻) → **标题**(主色,最醒目) → **正文**(正文色) → **结论**(主色,字号略小于标题)。
- 编号可保留编辑感（宋体/衬线），但建议略缩小、颜色略淡，不压标题视觉权重。

### 11.2 页眉节奏（section_header）
- 顺序：**主标题** → 短规则线（紧贴标题下方 ~0.07″，读作"下划线"）→ **副标题**（与线底留 ~0.17″ 空气）。
- 规则线须与标题左缘**严格对齐**。
- **反模式**：规则线悬空在标题与副标题之间（距标题 0.23″、距副标仅 0.06″）→ 视觉"焊死"副标、重心偏下（商务/文质 P3 均踩过，已修）。

### 11.3 底部结论（bottom_gold）
- **金句上方无分隔线（2026-08-01 通用规则，四风格一致）**：居中金句本身即收尾，强调色只点关键词；`common.bottom_gold` 已删画线，`line_color/line_y` 弃用。
- **否决"独立结论带"**（浅金底+青标签+局部金词）：多一层视觉重量、与简洁金句抢戏，且用户已明确否决。
- 卡内结论上方的细分隔线 `card_divider` 不在此列，保留（卡内结构分隔，非金句装饰）。

### 11.4 字体分工（两种语言）
- 页面主标题：衬线/宋体（观点与气质）。
- 卡片标题/正文/信息：黑体（阅读效率）。
- 一页内同类字重/同字体不宜过多，否则降低技术内容清晰度。

## 12. 反模式清单（勿再犯）

1. 一处页面 ≥3 个"最高优先级"焦点（强调色滥用于 编号+卡片结论+页底）。
2. 卡片阴影 35% 重投影（旧默认，已弃用）→ 须 ≤8%。
3. 页眉规则线焊死副标题（悬空 0.23″ 又贴 0.06″）。
4. 底部加"独立结论带"抢戏（用户否决）。
5. 卡片标题加大突破四风格统一锁值（用户红线）。
6. 只信"运行没报错"不反向读 XML 验证（形状数/坐标/prstGeom/越界/阴影 alpha）。

## 13. 验证闭环（强化）

- 每次生成后必跑 `common.validate_deck(path)`。
- **#6 阴影检查**：扫描所有 `a:outerShdw` 透明度，>12% 报 WARN（设计纪律提醒，**非阻断**，避免误伤既有 deck）。
- 反向读 XML 核对：强调色出现处计数、阴影 alpha、边框色、越界。
- **解析坑（血泪）**：形状元素是 `p:sp`（presentationml 命名空间 `http://schemas.openxmlformats.org/presentationml/2006/main`），**不是** `a:sp`（drawingml）；坐标在 `<a:off x=".." y="..">`。用 `p:sp` 迭代，否则遍历不到形状、全部漏检。
- **文件锁**：输出文件被 PowerPoint 预览打开时会锁住，`save` 报 `PermissionError` → **改输出文件名（v2/v3）**，不覆盖、不删。
