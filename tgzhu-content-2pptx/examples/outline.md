## 第 2 页 — 案例原始需求

标题: 一个数据采集的自动化设计案例 —— 原始需求

// 需求描述
我需要全国每个城市/区县、每周近实时的新能源汽车销量数据，为业务经营提供数据支撑。

// 需求目标
从互联网公开信息中合法采集新能源电动汽车的周/月销量数据，形成明确到城市及区县的统计表，经清洗校验后导入 SQL Server。

// 引出问题
传统做法：人手动找数据→写爬虫→清洗入库，几天到一周。AI 来做，会有什么不同？

## 第 3 页 — 案例设计过程

标题: 案例设计过程 —— 人和AI如何分工

// 传统研发 vs AI 协作
| 环节 | 传统研发 | AI协作模式 |
|------|---------|-----------|
| 需求分析 | 人写文档 | 人定目标，AI复述确认 |
| 数据调研 | 人手动搜索 | AI主动发现缺口，人确认 |
| 方案设计 | 人设计方案 | AI出方案，人决策 |
| 编码实现 | 人写代码 | AI编码，人校验 |
| 测试验证 | 人写用例 | 人设标准，多轮校验 |
| 交付部署 | 人部署 | AI封装，人验收 |

// 人的职能转变
传统研发：需求者→设计者→编码者→测试者→部署者
AI协作：目标定义者→方案决策者→结果校验者→验收负责人
→ 人的角色从"执行者"变成了"把关人"

## 第 6 页 — 理解AI：AI工程体系

标题: AI 工程体系（五层总览）

正文:
- L1 Prompt：怎么让模型听懂 — 指令、格式、示例
- L2 Context：该给模型什么信息 — RAG、Memory、MCP
- L3 Harness：怎样安全执行 — 规则、权限、验证、观测
- L4 Loop：怎么跨轮次推进 — 触发、状态、重试、协作
- L5 Meta-Loop：怎么持续优化 — 评估、比较、沉淀、回滚

关键理解：
- 五层是嵌套关系，后一层包含前一层
- 这不是理论框架，是从实践中总结出的 AI 工程体系

## 第 7 页 — 理解AI：框架对应五层与对比

标题: 当前热门框架工具，各解决了五层中的哪一层？

// 框架与层级的对应关系
- OpenClaw → L3 Harness + L4 Loop。侧重让Agent接入系统并持续执行
- Hermes → L5 Meta-Loop。侧重经验沉淀和Skill复用
- WorkBuddy → L1-L4 产品化。侧重任务交付和办公场景
- baoyu 系列 → L2 Context 延展。侧重内容生成和视觉输出

| 框架 | 类型 | 侧重点 | 上手 | 适用场景 |
|------|:----:|--------|:----:|---------|
| OpenClaw | 开源 | 执行治理 | 中 | 自动化任务编排 |

| WorkBuddy | 商业 | 产品交付 | 低 | 办公文档产出 |
| baoyu 系列 | 开源 | 内容生成 | 低 | 视觉内容创作 |

// 关键理解

## 第 8 页 — 实操AI：不同岗位能用AI做什么

// 岗位与AI能力
| 岗位 | AI 现在能做的 | 实在例子 |
|:----|:------------|:---------|
| 研发 | 代码生成、调试协助、方案设计、文档产出 | 自动写数据清洗脚本、生成单元测试、辅助接口联调 |

## 第 9 页 — 实操AI：做高质量PPT（路线A）

标题: 实操AI —— 制作高视觉效果PPT

// 路径A：高视觉方案（耗时耗钱）
- 工具链：ChatGPT Image 生成单页 → GordenImage2PPTX 转可编辑
- 优点：视觉效果精致，适合正式汇报场合
- 缺点：API额度消耗大，反复调试成本高
- 适合场景：产品发布会、对外宣讲、重要汇报

// 关键流程
1. 用 ChatGPT Image 生成产品介绍图（单页视觉设计效果好）
2. 再用 GordenImage2PPTX 还原成可编辑 PPTX
3. 后续微调文字、移动元素、统一风格

## 第 10 页 — 实操AI：做日常PPT（路线B）

标题: 实操AI —— 制作日常技术交流PPT

// 路径B：日常方案（低成本通用）

| 快速原型/头脑风暴 | 路径B：日常方案 | 快速出稿，迭代修改 |

// 核心结论
让正确的AI做正确的事——不是所有PPT都需要高视觉，也不是所有场合都适合低成本方案。

## 第 11 页 — 驾驭AI：问题怎么解决

标题: 驾驭AI —— 今天实战中遇到的问题与决策

// 尝试过的路线
| 方案 | 结果 | 问题 |
|:----|:----|:----|
| baoyu-slide-deck 生成图片 | ❌ | 不可编辑 |
| PptxGenJS 代码绘制 | ❌ | 6轮无法对齐模板 |
| ImageGen + 模板参考图 | ❌ | Logo/位置不精确 |
| 模板克隆 + 文字替换 | ✅ | 样式统一可编辑，视觉靠微调 |

// 关键判断
- 内部技术分享 → 内容完整 > 视觉精美
- 代码绘制有边界 → 不是AI问题，是工具限制
- 模板克隆保证一致 + 可编辑 → 美化交给PPT微调
- 流程沉淀为规范 → 不可复用才是真浪费

// 结论
驾驭AI不是让AI做所有事，而是让正确的人基于场景做正确决策。
